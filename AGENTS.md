# QR-меню и приложение для кафе (Вьетнам, Фантьет / Муйне) — полное описание проекта

Этот файл — полная передача проекта: что это, как устроено, как собирать, что уже решено с заказчиком, что в работе и что запланировано. Читать целиком перед любой правкой. Короткая версия того же для Claude Code — `CLAUDE.md` (держать оба файла в согласии).

Проект Марго: многоязычные QR-меню для кафе (продаём вьетнамским владельцам) и приложение для персонала (официант / кухня / владелец), которое принимает заказы из меню.
Сайт: https://dellviktoriapro.github.io/qr-menu/ (GitHub Pages, ветка `main`, корень репозитория). Репозиторий: `dellviktoriapro/qr-menu`.

## 4. Сборка

`PYTHONUTF8=1 python _src/build_all.py` — собирает: приложение → Chez Oanh → Sun&Sea → Lam Tong.

- **Приложение:** `_src/ops/tpl.html` — основа. `_src/demo/mk.py` накладывает русские строки и автоязык (RU/VI по языку телефона или `#ru` / `#vi` в адресе). `_src/demo/build.py` подставляет `__PH__` (иконки), `__CO__` (меню Chez Oanh для стоп-листа) и `__SS__` (меню Sun&Sea для стоп-листа). Каждая замена в mk.py проверяется `assert`: если шаблон изменился и строка не нашлась, сборка упадёт — поправить mk.py.
- **Меню Chez Oanh:** данные `_src/chez/data.py` (23 раздела, 296 позиций, 5 языков: en, vi, ru, ko, zh). Шаблон `_src/chez/tpl.html`. `build_web.py` пишет текстовую страницу и фото в WebP кусками по ~650 КБ (`ph1.js`…). Куски грузятся по очереди после текста через `__ph({...})`; до загрузки у картинок прозрачная заглушка. Иначе (всё в одном файле, 5 МБ) страница грузилась 44 секунды. `build.py` — однофайловая версия для артефакта на claude.ai.
- **Меню Sun&Sea:** `_src/sunsea/build_web.py` берёт **тот же движок `_src/chez/tpl.html`**, перекрашивает CSS, подменяет тексты кафе, ключи хранилища и канал в приложение, затем вставляет свои данные и фото. Каждая замена проверяется `assert` — если поменять движок, может упасть сборка Sun&Sea; тогда поправить замену в `sunsea/build_web.py`.
- **Lam Tong:** `_src/lam-tong/` (data.py, tpl.html, build.py) — старое меню, не на общем движке.
- **QR-таблички:** `_src/tables-qr/mk.py` + `pdf.js`. A4, 4 таблички на лист, ссылка `chez-oanh/?t=N`, столы 1–12 (реальное число столов не уточнено). Для Sun&Sea табличек ещё нет (адрес будет `sun-sea/?t=N`).

### Формат данных меню (`data.py`)
- Раздел: `sec(id, name, items, note=None, group='food'|'drinks')`, `name` = `L(en, vi, ru, ko, zh)`.
- Позиция Chez Oanh: `(en, vi, ru, ko, zh, price, photo)`. Позиция Sun&Sea: то же + 8-й элемент `extra` (dict).
- `price`: число (донги) | `None` (= «уточняйте у официанта», без кнопки «+») | список вариантов `[(label, price), …]` (label — `'S'`/`'B'` или `L(...)`).
- `photo`: ключ файла `ph/<ключ>.jpg` (нет файла → позиция без фото, идёт списком).
- `extra` (поддерживает движок, используется в Sun&Sea): `n` — номер в их меню, `d` — описание `L(...)`, `tg` — пометки (`special`, `best`, `must`, `signature`, `day`, `premium`, `preorder`, `hot`, `veg`), `nt` — пометка к цене `L(...)` (например «за штуку»).
- Ключ блюда в корзине/стоп-листе: `раздел|номер` (корзина: `раздел|номер|вариант`).

## 5. Меню гостя (общий движок, Chez Oanh и Sun&Sea)

- **Язык:** при первом входе экран выбора языка (RU, EN, VI, KO, ZH), потом кнопка языка. Цены в донгах + пересчёт в валюту языка (курс вручную в `RATES`, дата `RATE_DATE`).
- **Стол:** номер берётся **только из QR на столе**: `?t=5`, хранится 5 часов. Без номера (общая ссылка) «Заказать» сначала просит выбрать стол 1–12 (`NT`). Режима «Показать официанту» больше нет.
- **Компоновка (v2):** компактная шапка (у Chez Oanh — лев; название, «Стол N», ссылка «О кафе»). Под ней **закреплённая полоса**: поиск + «Еда / Напитки» + круглые разделы (подсвечивается текущий; плавающая кнопка языка прячется, пока полоса прилипла; **колесо мыши над строкой разделов прокручивает её вбок**). Блюда с фото — плитки (2 в ряд на телефоне, 3 на планшете), без фото и добавки — списком под плитками. Адрес, часы, Wi‑Fi, преимущества — в блоке «О кафе» внизу.
- **Карточка блюда:** нажатие на плитку/строку открывает шторку: большое фото (нажатие — на весь экран), название, оригинал, описание, пометки, варианты с ценой и кнопкой.
- **«В корзину»:** фото летит в нижнюю капсулу, капсула подпрыгивает, вибрация (учитывается prefers-reduced-motion). Пожелания: «без сахара», «без льда», «не остро»…
- **Капсула внизу** (одна вместо трёх полос): кружки гостей / число позиций, сумма, «Заказать» (после заказа — «Счёт»). Нажатие открывает **шторку стола**: живой статус, гости («+ Гость»), «Попросить счёт», «Оплатить по QR», «Чаевые».
- **Заказ:** «Заказать» отправляет в приложение. Гость видит «Заказ отправлен», корзина очищается, можно дозаказать.
- **Раздельные чеки:** при первом блюде вопрос «Счёт общий или раздельный?». Раздельный → гость называет чек («Анна»), сразу спрашивается «Кто ещё платит отдельно?». Блюда идут в активный чек. Заказ уходит по одному на чек (поле `check`). Если выбрали общий — в корзине кнопка «Разделить счёт». Очистка корзины — окно «Отмена / Да, очистить». Разные телефоны за одним столом ведут свои чеки независимо (без сервера общего списка нет).
- **Счёт и оплата:** «Попросить счёт» (наличные / карта, можно выбрать чек) и «Оплатить по QR-коду» (сумма + **статичный QR владельца**, загруженный в приложении; «Я оплатил(а)» шлёт официанту «гость отметил перевод — проверьте»). Банк и касса не подключаются — перевод на личную карту.
- **Чаевые:** блок внизу меню + кнопка в окнах оплаты. Показывает QR официанта, который принял заказ стола (иначе — «чаевые можно оставить после того, как официант примет заказ» / «официант не добавил QR — наличными»).
- **Живой статус:** приложение публикует заказы открытых счетов по столам. Меню показывает «Ваш заказ #N» с шагами Отправлен → Принят → Готовится → Несём → Подано и подписью («Minh несёт заказ к столу»), в капсуле — текущий статус. Только заказы текущего визита (`*_guest.ord0`). Обновление по событию storage и раз в 3 с.
- **Стоп-лист:** блюда из стоп-листа приглушены с пометкой «Закончилось», без «+»; если уже в корзине — удаляются с уведомлением (проверка раз в 10 с и по storage).
- **Отзывы:** после «Я оплатил(а)» или когда официант закрыл стол — окно «Спасибо, что были у нас!» с кнопками на Google Карты и Tripadvisor (ссылки вводит владелец). Один раз за визит, без ссылок не показывается. Закрытие стола завершает сессию гостя (чеки, кнопки счёта).

### Мост меню ↔ приложение (только демо!)
Сейчас всё через `localStorage` + `BroadcastChannel` — **работает только в одном браузере** (для показа владельцу). Для реальной работы нужен сервер (§10).
- Меню → приложение: `co_inbox` (Chez Oanh) / `ss_inbox` (Sun&Sea) — массив сообщений `{id, table, lang, at, type:"order"|"bill", items[{key,q,vi,ru,en,p,st}], wishes, check, pay, paid}`.
- Приложение → меню: `co_pub` / `ss_pub` — `{pay: QR владельца, w: {id:{n,qr}} официанты и их QR чаевых, t: {стол: официант}, stop: [ключи], rev: {g, ta}, closed: {стол: время закрытия}, ord: {стол: [{no, st, w, at, ck}]}}`.
- Ключи сессии гостя: Chez Oanh `co_cart, co_wish, co_ck, co_guest, co_tbl, co_lang, co_cur`; Sun&Sea — те же с префиксом `ss_`.

## 6. Приложение персонала (`demo/`)

- **Заведения:** кнопка с домиком рядом с названием → Café Chez Oanh или Sun&Sea Restaurant. Владелец «входит» в своё и видит только его: заказы, счета, сотрудников (у Sun&Sea свои имена: Tuấn, Hoa, Long, Bảo, Hải, Vy), код подключения (`CO-7F3K` / `SS-4M2Q`), стоп-лист по своему меню, QR оплаты, отзывы, аналитику. Настройки — объект `CAFES` в `ops/tpl.html` (`sfx` хранилища, `inbox`/`pub` канал, `mk` префикс ключей меню, блюда для устных заказов `MENU_CO` / `MENU_SS`, меню стоп-листа `CO` / `SSD` → `CMENU`). Выбор в `ops_cafe`, переключение перезагружает приложение. Данные: `co_ops_demo_v2` (Chez Oanh) и `co_ops_demo_v2_ss` (Sun&Sea).
- **Роли:** Официант, Кухня («Повар / бар»), Владелец (и управляющий), Новый сотрудник. «Все экраны» — официант и кухня рядом (видна у владельца, на телефоне тоже). Окна «Гость» нет — гость заказывает через меню.
- **Поток:** QR-заказ → уведомление официантам → официант принимает, уточняет, правит, комментирует → «Отдать в работу» → кухня/бар отмечают блюда → «Готово» → уведомление официанту (с эскалацией на всех, настраивает владелец); на экране кухни подтверждение «Официант X получил уведомление».
- **Счёт на стол:** все заказы и дозаказы стола — один счёт, дозаказы помечены. «Вынес» ≠ оплачено: вынесенный заказ остаётся в открытом счёте. Закрывает только официант после оплаты («Оплачено · закрыть стол», подтверждение повторным нажатием).
- **Как оплатили:** при закрытии — три крупные кнопки с иконками (Наличные / Карта / Перевод по QR), выбранная залита медью; при раздельных чеках строка на каждый чек; подставляется из просьбы гостя; без отметки стол не закрывается (блок краснеет и встряхивается). Хранится в `bill.pays` / `bill.pay` (или `mix`).
- **Вкладки официанта:** Новые · Мои · Готово · Вынесено (счёт открыт) · Завершённые (оплачено, «Оплачено · способ») · Столы (в конце, по просьбе Марго).
- **Столы:** «Карта зала / Список». Зал — столы 1–8, терраса — 9–12 (+ выше 12, если есть счета). Состояния: свободен (пунктир), новый заказ (серебро, пульс), готовится (сталь), готово (медь, свечение), просит счёт (красный, пульс), **занят** (всё вынесено). Нажатие: открытый счёт → счёт; свободный → устный заказ на этот стол. Расстановка условная — заменить по плану кафе.
- **«+ Устный заказ»:** круглая плавающая кнопка внизу справа у официанта.
- **Свайп:** смахнуть карточку вправо = её главная кнопка (Принять / Отдать в работу / Вынес).
- **Дозаказ** идёт сначала официанту этого стола; через 40 с (`REORDER_MS`) или если он не на смене — всем.
- **Просьба о счёте:** уведомление официанту стола (или всем), красная плашка, пульсирующий стол.
- **Подключение сотрудников:** сотрудник сканирует QR кафе → имя и телефон → заявка владельцу → владелец подтверждает и выбирает роль; может менять роль, блокировать, удалять (история сохраняется), перевыпускать код. Журнал действий. **PIN-вход не нужен** — решение Марго.
- **QR оплаты и чаевых:** владелец загружает статичный QR своей карты во вкладке «Сотрудники» (пока нет — красная плашка). Официант — свой QR для чаевых при подключении или кнопкой «QR для чаевых» (пока нет — кнопка медная и пульсирует). Фото ужимается до 640px JPEG.
- **Стоп-лист:** повар (Кухня → «Стоп-лист») и управляющий/владелец (Владелец → «Стоп-лист»): «Закончилось» / «Вернуть» по всему меню своего заведения, поиск по названию.
- **Отзывы:** владелец во вкладке «Сотрудники» вводит ссылки на Google Карты и Tripadvisor (только https://).
- **Аналитика владельца:** выручка, чеки, средний чек, время принятия, время готовки, официанты, топ блюд, языки гостей, способы оплаты, выручка по часам и по дням. Периоды: Сегодня / Вчера / 7 / 30 / 90 дней / свой (до 180 дней), сравнение с прошлым периодом (▲▼%), «Скачать для Excel» (CSV, «;», UTF-8 BOM). Дни — по времени Вьетнама (UTC+7). В демо прошлые дни — детерминированная примерная история (`genDay`); с сервером заменится запросами.
- «Сбросить» в демо обнуляет заказы, но сохраняет QR оплаты, ссылки на отзывы и QR чаевых; очищает и сессию меню своего заведения.
