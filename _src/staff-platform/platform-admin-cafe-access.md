# Доступ администратора платформы к кафе

Администратор входит под своей учётной записью в `/app/`. Карточка каждого активного кафе содержит кнопку «Войти в кабинет». Рабочий кабинет открывается в той же сессии, со всеми экранами и действиями владельца; кнопка «Мои заведения» возвращает к общему списку. Публичные меню не меняются.

Источник полномочий — `rp_private.platform_admins.active` и подтверждённая учётная запись в Supabase Auth. `rp_private.my_cafes()` добавляет админу все активные кафе. `rp_private.require_member()` и серверные шлюзы сотрудников проверяют роль на каждом запросе. Если роль администратора отозвана, доступ к чужим кафе прекращается.

Администратор не становится владельцем ресторана. Для существующих внешних ключей заказов и действий при первом входе создаётся **неактивная** техническая запись `rp_memberships` с ролью `manager`; во время авторизованного запроса сервер возвращает эффективную роль `owner`. Эта запись скрыта из списка команды и не блокирует приглашение реального владельца. Изменять техническую запись через кабинет сотрудников запрещено.

Порядок выпуска: выполнить `platform-admin-cafe-access.sql` в SQL Editor проекта Supabase; затем выполнить `platform-admin-cafe-access-test.sql` (весь тест идёт в транзакции с `ROLLBACK`); затем собрать `python _src/staff-platform/build.py` и опубликовать `app/`. Тест проверяет вход администратора в Sun&Sea, доступ к заказам и сотрудникам, скрытие технической записи и отсутствие доступа владельца Chez Oanh к чужому кафе.
